Mitarbeiten an der Website

Onboarding-Anleitung für das Projekt (Vorlage: Namen, Rollen und Zugänge anpassen) · Stand Oktober 2026

Die Einrichtung dauert für dich als Nutzer vermutlich nur etwa 10 Minuten, sofern die Vorarbeit (Abschnitt 2) erledigt hat. Du brauchst keine Programmierkenntnisse: Texte änderst du im Live-Editor, alles Weitere übernimmt Claude Code.

2. Einmalig durch (Inhaber, Vorarbeit)

Dieser Abschnitt ist für die Transparenz enthalten. Du musst hier nichts tun.

  1. GitHub: Organisation → People → Invite member (oder Repo → Settings → Collaborators) und Schreibrechte (Write) auf website vergeben.
  2. Claude-Zugang klären: Wer mit Claude Code arbeitet, braucht einen eigenen Zugang (Pro, Max oder Team-Seat). Ein gemeinsamer Account ist nicht vorgesehen.
  3. Schutz: Zwei-Faktor-Anmeldung für alle mit Schreibrechten, Schreibrechte nur an Vertraute. Eine technische Freigabe für Produktion (Required reviewers, Branch-Schutz mit Pull-Request-Pflicht) gibt es erst im bezahlten GitHub-Plan. Bis dahin gilt: ein live-…-Tag geht sofort live.
Niemals weitergebenSFTP-Zugangsdaten und der Deploy Key von . Sie sind nur als Secrets in GitHub hinterlegt. Du brauchst sie nicht, denn dein Rechner lädt nie selbst auf den Server.

3. Einrichtung auf deinem Rechner (macOS)

Schritt 1: GitHub-Account

Auf github.com registrieren (falls noch nicht vorhanden), Zwei-Faktor-Anmeldung aktivieren und die Einladung zur Organisation annehmen. Gib deinen Benutzernamen.

Schritt 2: Claude (nur für Claude Code)

Claude-Desktop-App von claude.ai/download installieren, mit deinem Claude-Zugang anmelden und den Tab Code öffnen.

Schritt 3: Git und Python 3

Im Terminal (Programme → Dienstprogramme → Terminal):

xcode-select --install

Das installiert Git und Python 3. Prüfen mit git --version und python3 --version.

Schritt 4: Projekt herunterladen

Einfachste Variante: GitHub Desktop (desktop.github.com), mit deinem GitHub-Account anmelden, File → Clone Repository → /-website. Zielordner zum Beispiel ~/Websites/-website.

Alternativ im Terminal (nach brew install gh und gh auth login):

mkdir -p ~/Websites && cd ~/Websites
gh repo clone /-website -website

Git braucht außerdem deinen Namen und deine Mail für die Änderungsprotokolle (einmalig):

git config --global user.name "Dein Name"
git config --global user.email "deine@mail.de"

Schritt 5: Testen, ob alles läuft

cd ~/Websites/-website
python3 build.py --preview

Es erscheint „Prüfung bestanden“ oder eine Liste mit Hinweisen. Dann ist die Einrichtung fertig.

4. Arbeiten: zwei Wege

Weg A: Texte ändern mit dem Live-Editor (ohne Claude)

  1. Im Projektordner Editor starten.command doppelklicken (beim ersten Mal Rechtsklick → Öffnen). Alternativ im Terminal python3 editor.py.
  2. Im Browser öffnet sich die Seite. Text anklicken, ändern, Speichern (⌘↵). Die andere Sprache steht daneben.
  3. Vor dem Veröffentlichen kurz im Team abstimmen (siehe Regeln). Veröffentlichen prüft die Texte und lädt sie hoch. Staging aktualisiert sich nach etwa 1 bis 2 Minuten.
WichtigDer Editor veröffentlicht derzeit direkt auf main. Arbeiten mehrere Personen gleichzeitig, kann der Upload mit einer Fehlermeldung abbrechen. Dann bitte nichts erzwingen, sondern oder Claude Code fragen. Eine mehrbenutzerfähige Version ist als nächste technische Aufgabe geplant.

Weg B: Größere Änderungen mit Claude Code

  1. In der Claude-App im Tab Code den Projektordner öffnen.
  2. Claude liest automatisch CLAUDE.md und kennt damit Aufbau, Regeln und Befehle des Projekts.
  3. Aufgabe beschreiben, zum Beispiel: „Lege einen Branch texte-startseite an und ändere …“. Claude baut, prüft und zeigt das Ergebnis.
  4. Commit und Pull Request nur auf Aufforderung: „Bitte committe und erstelle einen Pull Request.“

Tipp: Pro Thema eine neue Sitzung starten (z. B. „Landingpage X“, „Rechtstexte“). Das hält Claude fokussiert.

5. Spielregeln im Team

Sieben einfache Regeln, damit mehrere Personen sicher an derselben Website arbeiten.

1
Eigener Branch für größere ArbeitenKleine Textkorrekturen gehen direkt. Alles andere läuft auf einem eigenen Branch (z. B. landing-produkt-x) und kommt per Pull Request nach main.
2
Jeder Push auf main aktualisiert StagingStaging () ist nicht öffentlich auffindbar, aber erreichbar. Keine vertraulichen Inhalte hochladen.
3
Live geht nur über Als Website-Owner startet jede Veröffentlichung auf die Produktion () selbst. Nur setzt den Tag live-… oder startet den Workflow für production. Eine technische Sperre gibt es derzeit nicht (kein bezahlter GitHub-Plan): Der Tag geht sofort live, deshalb gilt die Regel verbindlich. Meld dich bei , wenn eine Änderung nach Prüfung auf Staging live gehen soll.
4
Immer beide Sprachen pflegenJede Änderung in content/de und content/en. Fehlt etwas, bricht der Build mit einer verständlichen Meldung ab.
5
Sprachregeln einhaltenEnglisch ist American English, „Digitization“ statt „Digitalization“, Menüpunkte in Title Case. Deutsch ist geschlechtsneutral. Das Glossar (content/glossary.json) prüft automatisch mit.
6
Keine Preise, keine externen Skripte oder SchriftenDie Website nennt keine Preise. Ohne Fremdeinbindungen braucht sie keinen Cookie-Banner.
7
Konflikte sind normalWurde dieselbe Stelle von zwei Personen geändert, entsteht ein Konflikt. Claude Code löst ihn auf („Löse den Merge-Konflikt“).

6. Wenn etwas nicht klappt

ProblemLösung
Push abgelehnt („rejected“, „non-fast-forward“)Erst holen: git pull --rebase, dann erneut pushen. Oder Claude Code fragen.
Editor lässt sich nicht öffnenPort 8777 belegt oder Editor läuft schon: altes Terminal-Fenster schließen und neu starten.
Build meldet Fehler im Glossar oder StrukturMeldung lesen, sie nennt Datei und Stelle. Meist fehlt eine Übersetzung oder eine verbotene Schreibweise wurde verwendet.
Staging zeigt noch alte Version1 bis 2 Minuten warten. Auf GitHub unter Actions prüfen, ob der Lauf grün ist. Browser mit ⇧⌘R neu laden.
Etwas ist unklar fragen oder Claude Code: „Erkläre mir, wie ich …“
